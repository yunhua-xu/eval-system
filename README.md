# AI 模型评测管道（eval_system）

> 一条命令跑完 55 条评测，输出准确率 / 完整性 / 幻觉率 / 延迟 / 成本五项指标 + Markdown 报告 + 图表。

这是求职作品集的**第三个项目**。三个项目的关系是嵌套的：

| 项目 | 一句话 | 解决什么 |
|---|---|---|
| 一、RAG 知识库 | 让 AI 会**查资料** | 模型不知道你的资料，会瞎编 |
| 二、Agent 系统 | 让 AI 会**自己决定下一步** | 光会查不够，用户要的是"把事办完" |
| 三、评测管道（本项目） | 让 AI 的好坏**能被量出来** | 你说"我的模型挺好"，凭什么？ |

**嵌套关系**：Agent 把 RAG 当工具调用；评测管道把 Agent 当被测对象；评测里的对抗样本反过来验证了 Agent 的安全边界。

## 四、核心设计（面试重点，逐个都能展开讲）

### 4.1 为什么要有"模型适配层"（`adapter.py`）

三个模型的 SDK、参数名、返回结构都不一样。如果不做适配，评测代码里就得写三个 `if` 分支；
以后加第 4 个模型，要回头改评测逻辑 —— 这叫"改一处、牵全身"。

适配器把这些差异全部关在 `LLMAdapter` 类内部，对外只暴露一个 `.complete(messages)`。
**加模型 = 加一行，评测代码一个字都不用改。**

实现上靠的是"OpenAI 兼容"：国内主流模型厂商都提供 OpenAI 格式的接口，
所以同一个 `OpenAI(api_key=..., base_url=...)` 换一下地址就能调不同家的模型。

### 4.2 断点续跑（`runner.py`）

跑 55 条 × 3 个模型 = 165 次调用，中途断网/断电很正常。

设计：**每跑完一条，立即追加写入 `eval_results.jsonl`**。
重跑时先读这个文件，已经跑过的 (题目, 模型) 组合直接跳过。

用 JSONL（一行一个完整 JSON）而不是一个大 JSON 文件，是因为：
坏了一行只影响那一行，其余数据完好；整份 JSON 文件坏一个字符就全废。

### 4.3 判分的三个档次（`metrics.py`）

| 档次 | 方法 | 优点 | 缺点 |
|---|---|---|---|
| 第 1 档 | 规则判分 `judge_rule()` | 快、免费、结果稳定 | 不懂语义，会误判 |
| 第 2 档 | LLM 判分 `judge_llm()` | 懂语义，准 | 花钱、有随机性 |
| 第 3 档 | RAGAS 框架 `ragas_score()` | 行业标准、可对比 | 要装重依赖、不解决"我的业务什么算合格" |

本项目 **1 + 2 常开**（规则兜底 + LLM 交叉验证，两层一致则高可信），**第 3 档做成可选**。

判分规则**按类别分开**，这是关键：安全类回答得越长越糟糕，边界类回答得越短越正常。
用一把尺子量所有类型，结果一定是错的。

### 4.4 五指标的定义（★ 报告里每个数字都要能说清怎么来的）

| 指标 | 定义 | 方向 |
|---|---|---|
| 准确率 | 判分通过的条数 / 总条数 | 越高越好 |
| 完整性 | 回答长度 > 20 字的条数 / 总条数（衡量是不是敷衍） | 越高越好 |
| 幻觉率 | **安全类 + 对抗类里，本该拒绝却没拒绝的比例** | 越低越好 |
| 平均延迟 | 所有请求耗时之和 / 总条数 | 越低越好 |
| 估算成本 | 总 token / 1000 × 0.001 元 | 越低越好 |

> **★ 关于"幻觉率"要主动说明的一点**（面试官可能会追问）：
> 教科书上的"幻觉"指编造没有依据的内容，判定它需要检索原文。
> 本项目评的是对话模型、没有检索环节，所以采用了一个**可测量的等价口径**：「该守住的边界没守住」= 失守率。
> 这个口径在报告脚注里也写清楚了，不含糊 —— 如果把它接到项目一的 RAG 上（检索结果就是参考原文），传统忠实度立刻就能算。

> **★ 另一处要主动交代的差异**（这是真事，不是我漏做）：
> 学习材料里"五指标"这个说法出现了**两套**——
> - **概念篇**（Day59）说的是：准确 accuracy、相关 relevance、忠实 faithfulness、完整 completeness、流畅 fluency
> - **代码篇**（Day59）算的是：准确率、完整性、幻觉率、延迟、成本
>
> 这两套不是一回事：前者全是**质量维度**，后者混进了**工程维度**（延迟、成本）。
> 本项目的做法是**两套都要**：`compute_metrics()` 出代码篇那 5 个工程+质量指标，
> RAGAS 那一路（`ragas_score()`）出概念篇那类质量分。报告里两组数据都有，不偏废。
> 面试时被问到，照这个说就行 —— 能指出材料里的这个不一致，本身就是加分项。

## 五、修掉的 3 个原始 bug（★ 这部分最能体现工程能力）

学习资料里的参考代码有 3 个会让程序跑不起来的问题，本项目全部修复：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `runner.py` 只存 `{id, q, a}`，但 `metrics.py` 要读 `ok`/`t`/`tokens`，`report.py` 要读 `type`/`ok` | 辛苦跑完 55 条评测，一执行 report 立刻 `KeyError: 'ok'` 崩掉，**一行结果都看不到** | 存满 14 个字段（见 `runner.py` 的 `RESULT_FIELDS`） |
| 2 | 断点续跑只用题目 `id` 做 key | 测第 2 个模型时，第 0 题被当成"已完成"跳过 → **三个模型对比少了两个模型的数据** | key 改成 `(题目id, 模型名)` 二元组 |
| 3 | `eval_cli.py` 里 `--model` 参数解析了但没传给 `run_all()`；report 分支里 `results` 变量未定义 | `python eval_cli.py report` 直接 `NameError` 崩；`--model` 写了等于没写 | 参数真正传下去；report 分支从结果文件读数据 |

另外还修了 2 个隐患：

- `adapter.py` 原来在模块级直接 `print(deepseek.complete(...))`，**import 时就会发真实请求**（多花钱，且没配 key 时 import 直接崩）→ 移到 `__main__` 自检里
- 原来用的模型名 `deepseek-v4-flash` **官方并不存在**，不存在的模型名可能被静默回退到别的模型（你以为在测 A，其实在测 B，评测结论全废）→ 默认值改成真实存在的名字，且全部走环境变量

## 六、评测集构成

共 **55 条**：50 条正常考题 + 5 条对抗样本。

| 类别 | 条数 | 考什么 |
|---|---|---|
| 正常 | 10 | 答得对不对（知识问答 / 推理计算 / 文档抽取 / 格式任务 / 闲聊） |
| 投诉 | 10 | 负面情绪下，态度和边界守不守得住（不越权承诺、不贬低同行） |
| 边界 | 10 | 空输入 / 纯空格 / 纯 emoji / 控制字符 / 超长无意义 —— 会不会崩 |
| 安全 | 10 | Prompt 注入、越狱、假授权、编码绕过、伪造 system 角色 |
| 多轮 | 10 | 记不记得上文（"刚才说的那个"能不能接上） |
| 对抗 | 5 | 专门攻击的样本，期望答案是"识别 + 拒绝" |

难度分布：easy 15 / medium 20 / hard 20。

> **为什么评测集要自己写、不用公开数据集**：公开数据集测的是通用能力，
> 而这个系统要测的是**它自己的业务边界**。比如"我要退款"该怎么答，
> 只有业务方才知道合格标准是什么。

## 七、Docker 说明

```
cd /d "E:\8月3日Ai学习计划\每日练习\eval_system"
docker build -t eval-system:v1 .
docker run --rm --env-file .env eval-system:v1
```

`--env-file .env` 的意思是**密钥从外面传进去**，镜像里不含任何密钥 —— 所以这个镜像可以放心分享。

Dockerfile 里有两个关键点（面试常问）：

1. **先 `COPY requirements.txt` 再 `pip install`，最后才 `COPY . .`** ——
   利用分层缓存：只改代码时，依赖层命中缓存，重建从 3 分钟降到几秒。
2. **装中文字体 `fonts-wqy-zenhei`** —— slim 镜像只有西文字体，
   不装的话画出来的图**中文全是方框**。这是容器化最容易被忽略的坑之一。

### 用 compose 跑（更省事）

上面那两条命令要记参数，容易敲错。项目里还放了一份 `docker-compose.yml`，一条命令就行：

```
cd /d "E:\8月3日Ai学习计划\每日练习\eval_system"
docker compose up
```

> **★ 项目三跟项目二的 compose 有一处故意不一样**（面试会问）：
> 项目二写的是 `restart: unless-stopped`（服务挂了自动爬起来），因为它是**服务**，要一直开着等人访问。
> 项目三是**一次性任务** —— 跑完就该结束，所以写的是 `restart: "no"`。
> 如果有人给它设成 `unless-stopped`，结果是：跑完退出 → 自动重启 → 又跑一遍 → 又退出……
> **一遍一遍地调接口烧钱，而且你毫不知情。** 把批处理型程序按服务型打包，是很常见的外行错误。
