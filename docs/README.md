# docs 目录说明

这个目录**只放一样东西：面试展示用的截图**。

## 为什么要有这个目录

面试官扫一个项目的 README，通常只花 **30 秒**。

30 秒里他不会去读你的代码，也不会去数你的测试用例 —— 他会看**有没有图**。

> 一张雷达图，比 300 字的文字描述管用。

所以 `README.md` 第八节留了两个图位，对应这个目录下的两张图。

---

## 两张图是什么、怎么生成

| 文件名 | 里面是什么 | 怎么生成 |
|---|---|---|
| `报告截图.png` | `eval_report.md` 的**总体成绩表 + 模型对比表** | 跑完评测后，用 Markdown 预览器打开 `eval_report.md`，截那一部分 |
| `图表截图.png` | `eval_chart.png` 本身（柱状图 + 雷达图 + 散点图 三联图） | 跑完评测**自动生成**的，直接拷进这个目录 |

**完整步骤：**

1. 配好 `.env` 里的密钥
2. 双击项目根目录的 `跑全量评测.bat`（或者敲 `python eval_cli.py all --limit 0`）
3. 跑完会在项目根目录看到两个文件：`eval_report.md`（报告）、`eval_chart.png`（图表）
4. 把 `eval_chart.png` 拷成这个目录下的 `图表截图.png`
5. 打开 `eval_report.md`，截"一、总体成绩"和"模型对比"那两张表，存成这个目录下的 `报告截图.png`
6. **顺手把 `README.md` 第九节那张「实测结果」表填了** —— 数字就从 `eval_report.md` 照抄

## ★ 关于假图，说清楚

**这个目录现在是空的，这是故意的。**

我不放占位图、不放示意图、不放"效果演示"这类糊弄的东西。理由很直接：

- README 里放了假的报告图，面试官一句"你现场跑一下看看"就要当场穿帮
- 而且一旦被发现在数据上做假，你说的**所有**东西他都会重新怀疑一遍
- 反过来，你诚实地说"这一块我还没跑，代码在这里，随时可以现场跑"，反而更可信

> 所以现在的状态是：**代码齐全、命令能跑、图位留空、README 第九节写的是「（待填）」。**
> 这是一个诚实且完整的状态，不是一个"没做完"的状态。

---

## 什么时候这两张图会补上

跑完一次全量评测就会补上。跑之前先看一眼 `CHANGELOG.md` 的「待办」那一节 ——
那里列着当前所有还没验证、还没补的东西，一条一条划掉就行。
